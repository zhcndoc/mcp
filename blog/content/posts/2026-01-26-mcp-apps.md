今天，我们宣布 **MCP Apps 现已作为官方 MCP 扩展正式上线**。
工具现在可以返回可交互的 UI 组件，并直接在
对话中渲染：仪表板、表单、可视化、多步骤工作流等。
这是首个官方 MCP 扩展，并且已可用于生产环境。

{{< youtube bluAmTHoEow >}}

我们在[去年 11 月](https://blog.modelcontextprotocol.io/posts/2025-11-21-mcp-apps/)提出了 MCP Apps，建立在
[MCP-UI](https://mcpui.dev) 的出色工作以及
[OpenAI Apps SDK](https://developers.openai.com/apps-sdk/) 的基础之上。我们很高兴能与
OpenAI 和 MCP-UI 共同合作，创建一个共享的开放标准，为
开发者在其 MCP 客户端中包含 UI 组件提供支持。

从那以后，规范得到了进一步完善，SDK 也更加成熟，而 ChatGPT、Claude、
Goose 和 Visual Studio Code 等客户端已经推出了对此能力的支持，更多客户端
也即将到来。

## **什么是 MCP 应用？**

MCP 应用让工具能够返回丰富、可交互的界面，而不是纯文本。当某个工具
声明一个 UI 资源时，宿主会将其渲染在一个沙箱化的 iframe 中，用户可以直接在
对话中与之交互。

![Claude.ai 中运行的颜色选择器 MCP 应用](/posts/images/mcp-apps/claude-colorpicker-apps.gif)

以下是 MCP 应用大显身手的几个场景：

- **数据探索**：销售分析工具返回一个可交互的仪表盘。用户可以按地区筛选，
  下钻到具体账户，并导出报告，而无需离开对话。
- **配置向导**：部署工具展示一个包含依赖字段的表单。选择“生产环境”会显示
  额外的安全选项；选择“预发布环境”则会显示不同的默认值。
- **文档审阅**：合同分析工具以内联方式显示 PDF，并高亮相关条款。用户可以点击
  批准或标记某些部分，而模型会实时看到他们的决定。
- **实时监控**：服务器健康工具显示会随系统变化而更新的实时指标。无需重新运行
  工具即可查看当前状态。

如果这些交互以文本对话的形式进行，体验会不那么流畅；而 MCP 应用让它们变得
自然而然——就像在使用其他任何基于 UI 的 Web 应用一样。

## **工作原理**

MCP Apps 的架构依赖于两个关键的 MCP 原语：

1. **带有 UI 元数据的工具**：工具包含一个指向 UI
   资源的 `_meta.ui.resourceUri` 字段
2. **UI 资源**：通过 `ui://` 方案提供的服务端资源，包含打包的
   HTML/JavaScript

```javascript
// 带有 UI 元数据的工具
{
  name: "visualize_data",
  description: "将数据可视化为交互式图表",
  inputSchema: { /* ... */ },
  _meta: {
    ui: {
      resourceUri: "ui://charts/interactive"
    }
  }
}
```

主机获取该资源，将其渲染在一个受沙箱保护的 iframe 中，并通过 `postMessage` 上的 JSON-RPC 启用双向
通信。

## **为什么需要 MCP 应用？**

MCP 非常适合将模型连接到数据，并赋予它们执行操作的能力。但工具能够做什么，与用户能够看到什么之间，仍然存在一个上下文鸿沟。

设想一个查询数据库的工具。它会返回一组数据行，可能有几百行。模型可以对这些数据进行总结，但用户往往希望进一步探索：按某一列排序、筛选某个日期范围，或者点击查看某条具体记录。对于文本响应而言，每一次交互都需要再次提示。“只显示上周的那些。”“按收入排序。”“第 47 行的详细信息是什么？”这能用，但速度很慢。

MCP Apps 弥合了这一鸿沟。模型始终参与其中，能看到用户的操作并作出相应响应，而界面则处理文本无法胜任的部分：实时更新、原生媒体查看器、持久状态以及直接操作。二者结合后，就能以一个熟悉的界面，为模型和用户提供他们所需的全部上下文。

## **应用 API**

要构建新的 MCP 应用，开发者可以使用
[`@modelcontextprotocol/ext-apps`](https://www.npmjs.com/package/@modelcontextprotocol/ext-apps)
包，它提供了一个用于 UI 到主机通信的 `App` 类：

```javascript
import { App } from "@modelcontextprotocol/ext-apps";

const app = new App();
await app.connect();

// 接收来自主机的工具结果
app.ontoolresult = (result) => {
  renderChart(result.data);
};

// 从 UI 调用服务器工具
const response = await app.callServerTool({
  name: "fetch_details",
  arguments: { id: "123" },
});

// 更新模型上下文
await app.updateModelContext({
  content: [{ type: "text", text: "用户选择了选项 B" }],
});
```

由于应用运行在客户端内部，它们可以做普通 iframe 做不到的事情。它们可以记录
事件用于调试，在用户的浏览器中打开链接，发送后续消息以推动
对话继续向前，或者稍后悄悄更新模型的上下文。所有这些都通过标准的 `postMessage`
完成，因此你不会被绑定到任何框架。

## **安全模型**

在 MCP 服务器上运行 UI 意味着在你的 MCP 宿主中运行你没有编写的代码。MCP
Apps 通过多层机制来处理这一点：

- **Iframe 沙盒隔离**：所有 UI 内容都运行在具有受限权限的沙盒 iframe 中
- **预先声明的模板**：宿主可以在渲染前审查 HTML 内容
- **可审计消息**：所有 UI 到宿主的通信都通过可记录的 JSON-RPC 进行
- **用户同意**：宿主可以要求对 UI 发起的工具调用进行明确批准

如果某些内容看起来可疑，宿主可以在它渲染之前将其阻止。当然，用户
在连接 MCP 服务器之前，仍应主动而彻底地审查它们。

## **智能体式 UI 框架的未来**

[MCP-UI](https://mcpui.dev/) 和 [OpenAI Apps SDK](https://developers.openai.com/apps-sdk/)
开创了 MCP Apps 现已标准化的模式。这些项目证明了 UI 资源
完全可以自然地融入 MCP 生态系统，各种规模的企业都在生产环境中采用
OpenAI 和 MCP-UI SDK。

MCP-UI 不会消失。SDK 支持 MCP Apps 模式，其中 Client SDK 是
推荐给希望采用 MCP Apps 的 Hosts 的框架。社区也在持续为该规范
做出大量贡献。如果你已经在使用 MCP-UI，就继续使用它。
当你准备好时，迁移到官方扩展会非常直接。
