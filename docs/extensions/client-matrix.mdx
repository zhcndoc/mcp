此矩阵展示了哪些 MCP 客户端支持每个[官方扩展](/extensions/overview)。扩展始终是选择加入的：只有当客户端和服务器都在其[能力](/extensions/overview#negotiation)的 `extensions` 字段中声明支持时，客户端才会使用扩展。

<Note>

此列表由社区维护。如果您发现任何不准确之处或希望添加或更新信息，请 [提交拉取请求](https://github.com/modelcontextprotocol/modelcontextprotocol/pulls)。

</Note>

## 扩展概述

| 扩展                                                                                  | 标识符                                                     | 描述                                                             |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------- |
| [MCP Apps](/extensions/apps/overview)                                                 | `io.modelcontextprotocol/ui`                               | 在对话中以内联方式呈现的交互式 HTML 界面                         |
| [OAuth Client Credentials](/extensions/auth/oauth-client-credentials)                 | `io.modelcontextprotocol/oauth-client-credentials`         | 无需交互式用户登录的机器对机器身份验证                           |
| [Enterprise-Managed Authorization](/extensions/auth/enterprise-managed-authorization) | `io.modelcontextprotocol/enterprise-managed-authorization` | 通过企业 IdP 实现的集中式访问控制                                |
| [Skills over MCP](/extensions/skills/overview)                                        | `io.modelcontextprotocol/skills`                           | 发现技能并读取其说明和支持文件                                   |

## 为您的客户端添加扩展支持

如果您正在构建 MCP 客户端并希望实现扩展支持：

1. 查看扩展规范（例如，在 [ext-auth](https://github.com/modelcontextprotocol/ext-auth) 或 [ext-apps](https://github.com/modelcontextprotocol/ext-apps) 仓库中）
2. 在客户端在每个请求的 `_meta` 中发送的 `io.modelcontextprotocol/clientCapabilities` 的 `extensions` 字段中声明支持，并从服务器的 [`server/discover`](/specification/draft/server/discover) 响应中读取服务器的 `extensions`
3. 实现该扩展的协议要求
4. 提交 pull request 以更新此矩阵

请参阅 [扩展概述](/extensions/overview#negotiation) 以了解能力协商机制的详细信息。
