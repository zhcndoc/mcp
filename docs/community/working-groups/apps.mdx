<a id="group-type" />
## 组类型

**工作组**

<a id="mission-statement" />
## 使命宣言

MCP Apps 工作组定义、发展和维护用于通过 MCP 提供交互式用户界面的官方扩展。工作组负责监督扩展规范、SDK、参考实现、安全模型、兼容性工作和指导，以便应用能够在独立的 MCP 主机之间安全且一致地运行。

<a id="scope" />
## 范围

<a id="in-scope" />
### 范围内

- **规范工作**：[MCP 应用扩展规范](https://github.com/modelcontextprotocol/ext-apps/tree/main/specification) 和相关 SEP，涵盖 `io.modelcontextprotocol/ui` 命名空间下的以下区域。
- **应用程序生命周期**：应用程序如何声明、初始化、持久化和拆除，包括 UI 资源声明和工具元数据。
- **应用程序交互模型**：用户、应用程序和主机之间的交互协议，例如双向消息传递、应用程序工具等。
- **内容类型和渲染目标**：支持不同的内容类型和方法（例如生成 UI），并具有与 [A2UI](https://a2ui.org/) 和 [AG-UI](https://ag-ui.com/) 等外部协议的互操作性。
- **安全模型**：威胁模型、沙箱、安全策略、权限和 UI 发起操作的可审核性。
- **SDK 和参考实现**：[`@modelcontextprotocol/ext-apps`](https://github.com/modelcontextprotocol/ext-apps) SDK、参考主机、示例服务器和主机集成示例。
- **一致性**：兼容性测试、应用程序验证以及应用程序和主机的一致性要求的定义。
- **跨领域协调**：应用程序发现和元数据（通过注册表工作组）、代理流程中的 UI（通过代理 IG）以及每种语言的 SDK 支持（通过 SDK 工作组）。
- **文档**：API 参考、创作指南、主机集成指南、入门资源和示例。

<a id="out-of-scope" />
### 范围外

- **核心协议所有权**：对基本 MCP 语义、传输或生命周期的更改通过 [SEP 流程](/community/sep-guidelines) 提出，并由相关组或核心维护者拥有。
- **特定于主机的产品和设计决策**：主机控制其用户体验和视觉设计。工作组对互操作性和安全合同进行了标准化。
- **单独的应用程序实现**：基于扩展构建的应用程序仍然由其作者负责。
- **一般代理编排**：代理循环和子代理协调属于代理 IG，任务管理属于任务和事件工作组。该工作组仅涵盖交互式 UI 界面及其集成点。

<a id="related-groups" />
### 相关小组

- **代理 IG**：代理流程和任务生命周期内的交互式 UI。
- **[注册表工作组](/community/working-groups/registry)**：应用程序发现、分发和元数据。
- **[安全 IG](/community/interest-groups/security)**：沙盒、权限和 UI 启动操作的审查。
- **[SDK WG](/community/working-groups/sdk)**：TypeScript 参考实现之外的 SDK 一致性和支持。

<a id="success-criteria" />
### 成功标准

- 扩展规范、SDK、参考主机和示例得到积极维护，并能及时分类处理规范和 SDK 问题。
- MCP Apps 可以在多个主要主机之间无需修改即可运行。
- 兼容主机实现文档中规定的沙箱、权限、内容安全策略和可审计性要求，并通过兼容性测试套件进行验证。
- 破坏性更改很少发生，有文档记录，并且在更改前提供适当的弃用和迁移路径。
- MCP Apps 是智能体 Web 的标准 UI 层。
