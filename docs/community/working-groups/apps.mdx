## 组类型

**工作组**

## 使命宣言

MCP Apps 工作组定义、发展和维护用于通过 MCP 提供交互式用户界面的官方扩展。工作组负责监督扩展规范、SDK、参考实现、安全模型、兼容性工作和指导，以便应用能够在独立的 MCP 主机之间安全且一致地运行。

## 范围

### 范围内

- **规范工作**：[MCP Apps 扩展规范](https://github.com/modelcontextprotocol/ext-apps/tree/main/specification)及相关 SEP，涵盖以下 `io.modelcontextprotocol/ui` 命名空间下的领域。
- **应用生命周期**：应用如何声明、初始化、持久化和拆除，包括 UI 资源声明和工具元数据。
- **应用交互模型**：用户、应用和主机之间的交互协议，例如双向消息传递、应用工具等。
- **内容类型和渲染目标**：支持不同的内容类型和方法，例如生成式 UI，并与 [A2UI](https://a2ui.org/) 和 [AG-UI](https://ag-ui.com/) 等外部协议实现互操作性。
- **安全模型**：UI 发起操作的威胁模型、沙箱、安全策略、权限和可审计性。
- **SDK 和参考实现**：[`@modelcontextprotocol/ext-apps`](https://github.com/modelcontextprotocol/ext-apps) SDK、参考主机、示例服务器和主机集成示例。
- **兼容性**：兼容性测试、应用验证，以及应用和主机兼容性要求的定义。
- **跨领域协调**：应用发现和元数据（与 Registry WG 协作）、智能体流程中的 UI（与 Agents WG 协作），以及各语言 SDK 支持（与 SDK WG 协作）。
- **文档**：API 参考、创作指南、主机集成指南、入门资源和示例。

### 范围外

- **核心协议所有权**：对基础 MCP 语义、传输或生命周期的更改应通过 [SEP 流程](/community/sep-guidelines)提出，并由相关小组或 Core Maintainers 负责。
- **特定主机的产品和设计决策**：主机负责控制其用户体验和视觉设计。工作组负责标准化互操作性和安全契约。
- **单个应用实现**：基于该扩展构建的应用仍由其作者负责。
- **通用智能体编排**：智能体循环、任务管理和子智能体协调属于 Agents WG。本工作组仅涵盖交互式 UI 表面及其集成点。

### 相关小组

- **Agents WG**：智能体流程和任务生命周期中的交互式 UI。
- **[Registry WG](/community/working-groups/registry)**：应用发现、分发和元数据。
- **[Security IG](/community/interest-groups/security)**：沙箱、权限以及对 UI 发起操作的审查。
- **[SDK WG](/community/working-groups/sdk)**：SDK 一致性，以及 TypeScript 参考实现之外的支持。

### 成功标准

- 扩展规范、SDK、参考主机和示例得到积极维护，并能及时分类处理规范和 SDK 问题。
- MCP Apps 可以在多个主要主机之间无需修改即可运行。
- 兼容主机实现文档中规定的沙箱、权限、内容安全策略和可审计性要求，并通过兼容性测试套件进行验证。
- 破坏性更改很少发生，有文档记录，并且在更改前提供适当的弃用和迁移路径。
- MCP Apps 是智能体 Web 的标准 UI 层。
