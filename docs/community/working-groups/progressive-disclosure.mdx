## 组类型

**工作组**

## 使命宣言

渐进式披露工作组探索如何在协议维护的扁平列表之外组织 MCP 原语（Tools、Resources、Prompts、Tasks），以及这种组织方式如何同时惠及 MCP 服务器和客户端。该组记录来自客户端、服务器和网关的多样化需求，支持不同组织策略的参考扩展，并将建议反馈到 [SEP 流程](/community/sep-guidelines)，而不是过早选择某一种唯一的规范模式。

## 范围

### 范围内

- **需求收集**：记录用例和约束
- **模式探索**：测试并评估各种方法
- **概念验证**：维护一个共享仓库，用于存放参考实现和实验结果

### 范围外

- **批准规范变更**：本 WG 无权批准协议变更；建议通过 SEP 流程传递
- **实现强制要求**：该组可以记录模式，但不能要求特定的客户端或服务器行为

### 相关组

- **[工具注解 IG](/community/interest-groups/tool-annotations)** - 基于注解的原语过滤和选择与原语的组织和呈现相互交叉
- **[Skills Over MCP WG](/community/working-groups/skills-over-mcp)** - 维护已发布的 [Skills 扩展](/extensions/skills/overview)；技能发现和渐进式披露与分组存在重叠

## 问题陈述

由于多种原因，MCP 原语的扁平列表可能很长且难以使用。许多此类问题属于本组范围，但也有一些不属于本组范围。

**范围内**

- **上下文过载** - 原语列表加载到 LLM 的上下文中时，可能使模型不堪重负，导致混淆和选择不佳
- **操作效率低下** - 上下文中的长列表会消耗大量 token，从而增加处理成本和响应延迟
- **开发者体验不佳** - 缺少原语组织工具，使其更难管理和维护

**范围外**

- **用于安全的组织方式** - 根据权限级别向客户端组织和披露原语是一个重要问题，但超出本组职责范围
- **组织 MCP 服务器** - 服务器发现和注册表 schema 决策属于 [Registry WG](/community/working-groups/registry)，Skills Over MCP WG 负责提供技能分发需求

## 目标

1. **记录需求和经验** - 记录实现这些扩展的不同客户端、服务器和网关的多样化需求。我们**不会**试图尽早达成共识，而是旨在根据真实世界的经验记录其中的权衡
2. **参考扩展** - 许多可能的组织机制正在出现，现在可能还不是选择唯一规范模式的时机。不同服务器正在实现相似的功能，但缺少标准化限制了客户端有效利用这些功能的能力。本组将支持采用不同组织策略的参考扩展，例如分组、工具搜索和代码模式
3. **推广标准** - 邀请大型 MCP 服务器和客户端的开发者与维护者提供反馈，从定制实现迁移到标准化扩展

## 组织策略

有关每种策略的详细说明，包括既有实践、示例和讨论链接，请参阅 [Approaches](https://github.com/modelcontextprotocol/progressive-disclosure-wg/blob/main/docs/approaches.md)。

## WG 原则

1. **记录讨论** - WG 旨在记录权衡和讨论，而不是规定某一种特定实现。相比持续很久的 Discord 讨论，优先使用 WG 仓库中的 GitHub Discussions。同步 WG 会议的会议记录也会上传到 GitHub Discussions，供日后参考
2. **实验性扩展** - 该仓库存放不同方法的实验性扩展。扩展应至少支持 Python 和 TypeScript 实现，并包含（1）端到端的可运行演示，以及（2）其他人如何集成这些扩展的详细说明
3. **部署反馈** - WG 收集扩展用户的部署经验和反馈，以确定功能开发和变更的优先级

## 生命周期

**当前状态：积极探索**

### 退出标准

- 问题空间已解决（约定已建立，或已并入其他 WG）
- 参与度不足以维持发展势头
- 社区共识认为分组不属于 MCP 协议范围

## 交付物与成功指标

### 成功标准

- **短期**：记录需求共识并评估现有方法
- **中期**：明确建议（约定、协议扩展或两者兼有）
- **长期**：MCP 服务器和客户端之间可互操作的分组约定
