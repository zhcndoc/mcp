## 小组类型

**工作组**

<a id="mission-statement" />
## 使命宣言

文件上传工作组的存在是为了定义 MCP 工具和获取请求如何声明文件
输入，以便主机可以呈现本机文件选择器并将用户选择的文件内容传递到服务器。

如今，需要用户提供文件的服务器诉诸于要求 Base64 字符串的散文指令
或本地路径，这会产生不一致的用户体验并将编码详细信息推送给最终用户。本工作组
将指定一个最小的模式级机制来声明文件输入和有线格式
交付它们，锚定于 [SEP-2356](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2356)。

作为次要目标，工作组涵盖了工具如何返回对于 JSON-RPC 消息来说太大的文件
或者需要授权才能获取。

<a id="scope" />
## 范围

<a id="in-scope" />
### 范围内

- **规范工作**：SEP 定义工具输入模式上的声明性文件输入描述符和
  诱导请求模式、文件内容的有线编码以及主机端处理
  要求。
- **文件下载（次要）**：工具如何返回对于 JSON-RPC 消息来说太大的文件
  或者需要授权才能获取。上传工作优先。
- **参考实现**：`FileInputDescriptor` 的 SDK 类型和帮助程序、数据 URI 编码、
  以及演示选择器调用和值替换的示例主机流程。
- **跨领域问题**：与存在嵌入式 UI 表面的 MCP 应用程序工作组进行协调
  他们自己的文件选择器，以及安全 IG 的主机端验证要求。
- **文档**：涵盖文件输入声明和迁移指南的规范部分
  适用于当前使用 ad-hoc base64 指令的服务器。

<a id="out-of-scope" />
### 范围外

- 服务器到客户端的小文件传送，资源和 `BlobResourceContents` 已经涵盖了。
- 传输层或会话模型的更改。
作为设计工作的一部分，WG 可以评估流式传输、分块传输或预签名上传 URL 等方案；这些方案是落入初始 SEP 还是后续补充，由 WG 决定，而不是章程约束。

<a id="related-groups" />
### 相关小组

- **MCP 应用程序工作组** — 嵌入式应用程序 UI 可能会显示自己的文件选择器；描述符格式
  在这种情况下应该可以重用。
- **[Security IG](/community/interest-groups/security)** — 用户提供的文件内容的主机端验证要求（SEP
  参考资料 [OWASP ASVS V5](https://owasp.org/projects/asvs)
  用于一般上传卫生）。
- **工具注释 IG** — 文件输入描述符是输入参数元数据的一种形式，应该
  与更广泛的注释分类保持一致。
