## 工作组类型

**工作组**

## 使命宣言

Agents 工作组旨在使与由 agent 支持的系统之间的交互能够通过 MCP 实现互操作。如今，这些系统通常作为普通工具或通过特定框架的集成来提供，将持久执行、能力发现、委托和多轮交互留给临时约定。该工作组负责维护 Tasks，使其成为 MCP 持久异步执行的基础，并评估哪些剩余差距需要协议支持。基于生产环境用例和原型，工作组将演进 Tasks、引入与其互补的 Agents Extension，或记录应如何一致地使用现有 MCP 原语。

## 范围

### 范围内

- **Tasks**：稳定化
  [`io.modelcontextprotocol/tasks`](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2663)
  扩展并将其提升为 MCP 核心协议的一部分，包括收集实现反馈、解决歧义，以及评估针对其生命周期提出的变更。
- **Agents Extension 评估**：评估由 agent 支持的 MCP 用例，包括 agent-as-tool、remote-agent 和 supervisor/子 agent 模式，以确定是否需要 Agents Extension 来补充 Tasks。
- **原型和提案**：在有助于确定是否引入 Agents Extension、演进 Tasks 或依赖现有 MCP 原语的情况下，开发范围严格限定的概念验证。
- **实现协调**：与 SDK 和一致性维护者协调，针对工作组负责的规范收集实现反馈、示例和覆盖情况。
- **跨领域关注事项**：当 Tasks 或经评估的 agent 用例引发传输、事件、技能、授权、元数据或外部互操作性问题时，与相关工作组进行协调。
- **文档**：维护 Tasks 规范，并记录由 agent 支持的 MCP 用例、发现结果以及工作组采纳的任何提案。

### 范围外

- 构建或标准化通用 agent 框架和运行时，包括关于规划、记忆、模型选择和编排的内部决策。该工作组标准化 MCP 互操作性边界处的行为，而不是主机或服务器实现内部机制。
- 传输线路格式和会话机制，这些由 Transports WG 负责。
- 通用事件传递和回调机制，这些由 Triggers and Events WG 负责。

本章程不会预先决定推理或 agent 循环运行的位置，也不会预先决定特定能力应属于 Tasks、Agents Extension 还是现有 MCP 原语。工作组将通过设计工作评估这些问题。

### 相关工作组

- **[Transports WG](https://github.com/modelcontextprotocol/transports-wg)** — 任务轮询、多轮往返请求、无状态操作和请求关联依赖于传输和消息流语义。
- **[Triggers and Events WG](/community/working-groups/triggers-events)** — 主动的任务状态和完成通知属于事件传递范畴，由该工作组负责。

### 成功标准

- Tasks 根据实现反馈得到全面稳定，并从扩展提升为 MCP 核心协议的一部分。
- 阻碍 Tasks 稳定化的生命周期歧义和一致性差距得到解决，或被明确确定处理方式。
- 工作组发布关于是否需要 Agents Extension 来补充 Tasks 的评估，并以记录在案的用例和相关原型证据作为支持。
- 基于该评估，工作组将演进 Tasks、提出 Agents Extension，或记录现有 MCP 原语已足够。
- 在推进之前，通过原型和实现反馈对提出的 agent 协议表面进行评估。
