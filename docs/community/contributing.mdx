MCP 是一个欢迎社区贡献的开源项目。参与其中不需要先准备好要提交的改动。

您可以在[规范存储库](https://github.com/modelcontextprotocol/modelcontextprotocol) 中找到规范、这些文档和规范增强提案 (SEP)。每个 SDK 和工具在 [`modelcontextprotocol`](https://github.com/modelcontextprotocol) 组织中都有自己的存储库。

要使用 MCP 进行构建，请从 [服务器](/docs/develop/build-server) 和 [客户端](/docs/develop/build-client) 指南、[SDK 列表](/docs/sdk) 或 [MCP 注册表](/registry/about) 开始。

如果你想参与讨论，协议相关工作由[工作组和兴趣组](/community/working-interest-groups)组织。任何人都可以参加这些小组的会议，会议安排发布在 [meet.modelcontextprotocol.io](https://meet.modelcontextprotocol.io/) 上。[会议和频道](/community/working-interest-groups#meetings-and-channels)介绍会议的公告和记录方式。参加会议或发言、评论拉取请求、提交议题都不需要邀请或特定身份。

Discord 社区中也设有相应的工作组和兴趣组频道。

<a id="where-to-start" />
## 从哪里开始

<Steps>
<Step title="加入 Discord">

贡献者在 [Discord](/community/communication#discord) 上讨论协议。
</Step>
<Step title="找到合适的小组">

选择覆盖您所在区域的 [工作组](/community/working-interest-groups#current-groups) 或 Discord 频道。如果都不适合，请使用 `#general`。

要在规范存储库中找到工作，请阅读其[未解决的问题](https://github.com/modelcontextprotocol/modelcontextprotocol/issues) 或在小组频道中询问需要做什么。

以下部分涵盖了每种更改。
</Step>
<Step title="联系负责人">

每个小组的页面都会列出负责人。请在小组频道中说明你希望参与的工作。
</Step>
</Steps>

任何人都可以加入小组会议、对拉取请求发表评论或提出问题。参加前请查看[日历](https://meet.modelcontextprotocol.io/)并阅读[反垄断政策](/community/antitrust)。

<a id="report-a-problem" />
## 报告问题

[报告漏洞](/community/policies#reporting-a-vulnerability) 私下进行。

对于规范或这些文档中的错误、拼写错误或不清楚的文本，请打开一个[问题](https://github.com/modelcontextprotocol/modelcontextprotocol/issues/new/choose)。对于 SDK 或工具，请在该存储库中打开它。

请不要在存储库中发布使用问题。由于垃圾邮件，我们不再带他们去那里。

<a id="change-the-specification-or-docs" />
## 更改规范或文档

只有 `modelcontextprotocol` GitHub 组织的成员才能在规范仓库中创建拉取请求。成员资格根据对议题以及工作组或兴趣组的持续参与授予。[贡献者阶梯](/community/contributor-ladder#member)中的“成员”级别列出了具体要求，以及新成员的推荐方式。

组织成员遵循 [CONTRIBUTING.md](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/CONTRIBUTING.md#submitting-changes)。其他人按以下步骤参与。拼写错误、失效链接或小型规范缺陷等简单修复，只需完成第一步。
<Steps>
<Step title="提出改动">

使用[报告错误](https://github.com/modelcontextprotocol/modelcontextprotocol/issues/new?template=bug_report.yml) 表单提出问题并描述修复方法。在相关工作组的频道或 `#general` 中提出任何其他问题。成员或维护人员可以从那里获取它。
</Step>
<Step title="推送分支">

要提交改动本身，请推送到自己的分支，或你有写入权限的工作组仓库。规范修复放在 `docs/specification/draft/`，版本化指南的修复放在 `docs/docs/draft/`。带日期的目录存放已发布版本。每项改动只处理一个主题。有关环境设置和检查，请参阅 [CONTRIBUTING.md](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/CONTRIBUTING.md)。
</Step>
<Step title="请成员代开拉取请求">

在议题或频道中分享分支链接，并请成员或维护者代为创建拉取请求，同时注明你的贡献。
</Step>
</Steps>

对协议本身的更改需要 [SEP](#propose-a-protocol-change)。

<a id="work-on-an-sdk-or-tool" />
## 使用 SDK 或工具

MCP Inspector 和参考服务器只接受缺陷议题。
<Steps>
<Step title="阅读贡献指南">

每个存储库都设置自己的规则，以及一些没有分配问题的关闭拉取请求。如果存储库没有指南，请在其频道中询问，例如 `#python-sdk-dev`。
</Step>
<Step title="选择一个议题">

查找标记为 [`good first issue`](https://github.com/search?q=org%3Amodelcontextprotocol+is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22&type=issues) 或 `help wanted` 的议题，也可以新建议题。如果仓库指南要求，先申请将议题分配给你。
</Step>
<Step title="创建拉取请求">

对于任何比小错误修复更大的事情，请在编写代码之前就问题中的方法达成一致。
</Step>
</Steps>

[SDK 列表](/docs/sdk) 显示每个 SDK 的[层级](/community/sdk-tiers)，用于设置其问题分类时间。

<a id="propose-a-protocol-change" />
## 提出协议更改

协议变更需要经过 [SEP](/community/sep-guidelines)。错误修复和澄清[不需要](/community/sep-guidelines#when-you-need-a-sep)。

SEP需要一个[发起者](/community/sep-guidelines#sponsors)：一个工作组或核心维护者。
<Steps>
<Step title="查看路线图">

查看这个想法是否符合[路线图](/development/roadmap)当前的重点。符合优先领域的 SEP 会获得[优先审查](/development/roadmap#sep-prioritization)。
</Step>
<Step title="将其提交给工作组">

在其频道或会议上向覆盖该区域的[工作组](/community/working-interest-groups#current-groups)提出这个想法。如果该区域属于某个兴趣小组，则该兴趣小组可以通过[组建小组](/community/working-interest-groups#forming-a-group)流程启动一个工作组，并且该工作组赞助 SEP。 SEP 拉取请求[必须链接到该讨论](/community/sep-guidelines#workflow)。
</Step>
<Step title="起草由小组赞助的 SEP">

小组达成共识后，起草其愿意[赞助](/community/sep-guidelines#sponsors)的 SEP。在小组同意赞助前，提案应保留在草稿拉取请求中。附上符合[原型要求](/community/sep-guidelines#prototype-requirements)的原型；如果适合，也可以先将想法作为[扩展](/extensions/overview)发布。
</Step>
<Step title="提交核心维护者审查">

遵循[工作流程](/community/sep-guidelines#workflow)。此时你应已成为工作组成员，并有权在规范仓库中创建拉取请求（参阅[成员](/community/contributor-ladder#member)级别）。如果你尚无此权限，由工作组负责人创建拉取请求。SEP 赞助人将提案提交给核心维护者审查。
</Step>
</Steps>

<a id="other-ways-to-help" />
## 其他帮助方法

- 审查开放的 SEP 和草案规范拉取请求。
- 重现报告的错误。
- 使用草案规范测试 SDK 的候选版本。
- 编写[一致性](https://github.com/modelcontextprotocol/conformance)场景。具有可观察协议行为的标准轨道 SEP [需要一个](/community/sep-guidelines#conformance-test-requirement) 才能达到最终版本。

<a id="growing-your-role" />
## 发展你的角色

要扮演更大的角色，请参阅[贡献者天梯](/community/contributor-ladder)。 [治理](/community/governance) 涵盖谁决定什么，[MAINTAINERS.md](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/MAINTAINERS.md) 列出当前的维护者。

<a id="ground-rules" />
## 基本规则

- [行为准则](/community/policies#code-of-conduct) 适用于每个存储库、渠道和会议。
- [披露](/community/policies#ai-assisted-contributions) 拉取请求或问题中的任何 AI 协助。
- AI 代理必须遵循 [AGENTS.md](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/AGENTS.md)，这限制了他们可以打开问题和拉取请求的时间。
- 贡献内容已获得 Apache-2.0 代码和规范的许可，以及其他文档的 CC-BY-4.0 许可。
