## 组别类型

**兴趣组**

<a id="mission-statement" />
## 使命声明

Enterprise IG 负责识别和记录企业在生产环境中部署 MCP 时遇到的需求缺口。随着 MCP 在受监管行业和大型组织中的采用不断扩大，企业团队在身份验证集成、身份传播、审计与合规、网关行为、可扩展性与韧性以及配置管理等领域反复遇到缺口，而这些问题尚未在协议层面得到解决。本组汇集企业实践者，将这些缺口整理为问题陈述和结构化建议，并将其传递给相关工作组开展规范制定工作。治理和最佳实践模式可能会从这些讨论中产生，但本组的核心职责是挖掘协议层面的需求，而不是维护通用的最佳实践目录。

所有讨论和会议均以协议为重点，并且与供应商无关。Enterprise IG 不是进行产品推介或供应商营销的场所。参与者以分享部署经验和需求的实践者身份参与，而不是作为推广商业解决方案的代表。

<a id="scope" />
## 范围

<a id="in-scope" />
### 范围内

- **企业需求差距（总体重点）**：该小组的主要任务是确定目前 MCP 协议级别未解决的企业部署需求，并将其转化为相关工作组的问题陈述和建议。每个需求都与其代表的企业机会一起捕获，而不仅仅是痛点，因为缩小这些差距可以释放更广泛的企业采用和价值。通过该镜头探索以下特定领域；治理和最佳实践模式仅在出现协议级差距时才进行记录：
- **企业身份验证和身份**：讨论企业管理的身份验证模式，包括 IdP 集成（SSO、SAML、OIDC）、令牌生命周期管理、代表 (OBO) 令牌交换流程和细粒度授权（丰富授权请求）。收集通知授权 IG 和相关 SEP 的要求。
- **身份传播和会话上下文**：定义如何在 MCP 客户端、服务器和下游服务之间显示和传送经过验证的身份，以进行策略执行和审核。这包括衍生代理和委托代理用例：身份沿袭、子代理的最低权限、后代撤销以及跨多代理链的可审计性，这与身份验证相邻，但重点不同。
- **审计、可观察性和合规性**：探索 MCP 工具调用的标准化审计跟踪格式、与企业 SIEM 和可观察性平台的集成以及合规性框架的证据生成（SOC 2、HIPAA、GDPR、欧盟 AI 法案）。包括特定于部门的合规模式，例如医疗保健环境中的 PHI 处理和 BAA 范围的数据流。
- **网关和代理行为**：企业部署模式的文档，其中 MCP 流量通过 API 网关、负载均衡器、反向代理和安全代理进行路由。随着 2026 年 7 月 28 日版本转向无状态协议核心，焦点从会话亲和性转移到无状态模型中持续存在的差距：标头和上下文传播、跨代理的授权切换以及网关的策略执行。
- **可扩展性和弹性**：跨区域和可用区以企业规模运行 MCP。由于无状态核心可实现水平扩展而无需粘性会话，因此重点关注任务关键型部署的故障转移、负载分配和可靠性。
- **企业架构中的 MCP**：定义 MCP 如何融入更广泛的企业架构，包括与现有中间件、数据平台和代理编排层的集成。
- **配置可移植性和部署**：讨论跨异构客户端环境、多租户配置模式和企业规模部署实践部署 MCP 服务器的挑战。
- **拦截器和中间件**：探索 MCP 管道中请求/响应拦截的用例，包括 PII 编辑、合规性验证、内容过滤和幻觉检测。收集可能为未来中间件模式规范工作提供信息的需求。
- **问题陈述和用例**：记录企业痛点和生产故障场景（匿名），为规范工作的优先级建立证据基础。
- **给工作组的建议**：向授权 IG、安全 IG、网关 IG 和其他小组提供有关企业特定要求的结构化输入。

<a id="out-of-scope" />
### 范围外

- 编写或拥有SEP。企业 IG 生成问题陈述、用例和建议。具体规范的变更是通过适当的工作组推动的。
- 讨论特定于产品或特定于供应商的解决方案。讨论必须保持供应商中立，并重点关注协议级模式。
- 一般 MCP 支持或入门。该小组重点关注企业部署挑战，而不是介绍性 MCP 主题。
- 与授权 IG 的规范工作直接重叠。企业 IG 收集企业身份验证要求并将其提供给授权 IG，而不是提出身份验证协议更改。

<a id="related-groups" />
### 相关组

<a id="working-groups" />
#### 工作组

- **[传输工作组](/community/working-groups/transports)** — 企业支持的传输级需求（非功能性需求，例如延迟和水平扩展）被捆绑并作为传输工作组的输入提供。
- **扩展工作组** — 除授权之外的扩展要求被捆绑并作为扩展工作组的输入提供。

<a id="interest-groups" />
#### 兴趣组

- **[Authorization IG](/community/interest-groups/auth)** — 收集企业身份验证要求（IdP 集成、OBO 流、RAR）并将其作为 Authorization IG 规范工作的输入提供。
- **安全 IG** — 对运行时安全、工具中毒和凭证管理的兴趣重叠。企业IG侧重于组织和治理维度；安全 IG 专注于威胁模型和协议级缓解措施。
- **网关 IG** — 网关/代理行为模式直接重叠。 Enterprise IG提供企业部署上下文； Gateways IG 专注于网关技术规范。
- **金融服务 IG** — 一些企业关注点（合规性、审计、监管环境）与 FS-IG 重叠。将酌情协调交叉发布和联合会议。

<a id="decision-process-for-recommendations" />
### 建议决策流程

Enterprise IG 产出不具约束力的用例、问题陈述，以及功能性和非功能性需求。为确保清晰并避免下游流程争议，适用以下规则：

- **问题陈述和用例**通过 GitHub Discussions 或 Discord 主题异步提交，并在月度会议期间进行审阅。
- **向工作组提出的建议**通过参与者之间的懒共识最终确定，并在 GitHub 上发布，供为期 7 天的审阅。如果没有提出异议，则视为建议已获批准。
- **协调人**负责整理已批准的建议，并将其交付给相关工作组或兴趣组。
