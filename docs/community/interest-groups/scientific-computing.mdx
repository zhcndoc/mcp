## 小组类型

**兴趣组**

## 使命宣言

科学计算兴趣组探索 MCP 在科学和工程工作流中的使用场景。兴趣组从科研和行业从业者处收集使用场景，以了解哪些差距值得通过开发扩展或改进协议来解决，并可能因此组建工作组。

## 范围

### 范围内

- **数量、单位和不确定性**：表示带有计量单位的物理量、维度信息、工具输入和输出中的不确定性以及量的种类，使智能体和客户端能够建立用于强制执行物理约束的防护机制
- **可复现性和溯源**：记录通过 MCP 获取的计算结果所需的参数、软件和求解器版本以及其他输入
- **数组和数值数据集**：传递数组、张量、表格数据以及对于模型上下文而言过大的数据集，包括如何引用这些负载并将其传递给工具
- **长时间运行的计算**：模拟、求解器运行以及批处理或 HPC 作业提交，以及它们如何映射到 MCP 的 tasks 架构，以实现异步执行、进度和取消机制
- **与现有科学标准的互操作性**：确定 MCP 应如何关联既有的领域格式、词汇和本体，而不是重新发明它们
- **跨领域使用场景确定**：收集物理、化学、生物、地球与气候科学、天文学和工程领域的需求，并识别反复出现的需求

### 范围外

- **定义科学数据格式或词汇**：单位系统、文件格式和领域本体由现有标准机构和社区维护；本组讨论 MCP 如何与它们互操作，而不是如何设计它们
- **构建或维护领域 MCP 服务器**：特定软件包、代码或数据集的独立服务器是本组收集使用场景的重要输入，但构建这些服务器不属于协议工作
- **授权和身份机制**：OAuth 流程、作用域和令牌处理属于[授权 IG](/community/interest-groups/auth)

### 相关小组

- **[Agents WG](/community/working-groups/agents)**：Tasks 是高性能计算中长时间运行的模拟和作业提交工作流的基础
- **[Interceptors WG](/community/working-groups/interceptors)**：interceptors 是验证客户端和服务器之间的正确性并规范化单位的潜在实现路径
- **[File Uploads WG](/community/working-groups/file-uploads)**：必须考虑输入数据集、网格和几何文件以及其他大文件
- **[Primitive Grouping IG](/community/interest-groups/primitive-grouping)**：科学服务器通常会公开大型分层工具面，这促使人们寻求超越扁平列表的组织方式
- **[Registry WG](/community/working-groups/registry)**：为共享科学软件和数据集发布和发现服务器，与注册表元数据有关
