<a id="discord" />
## Discord

[MCP 贡献者 Discord](https://discord.gg/6CSzBmMkjX) 适合从事协议及其项目的人员，也是协议及其设计讨论的起点。它不是支持渠道：将可重现的错误报告为其影响的存储库上的问题，并从文档开始了解有关使用 MCP 的问题。不要在服务器上推销产品或服务，并且仅将供应商作为与规范相关的示例来提及。

用于项目范围讨论的频道命名为 `#general`，每个工作组和兴趣组的频道命名为 `#<name>-wg` 和 `#<name>-ig`，每个 SDK 的频道命名为 `#<lang>-sdk-dev`。其他项目有 `#inspector-dev` 等频道。在 `#wg-ig-group-creation` 中提议一个新组。我们将尽力做出回应。

频道默认是公开的。私人渠道仅限于指定的维护者和社区版主，并且仅适用于安全事件（CVE 和协议漏洞）、人员和行为准则问题以及需要有限受众立即或集中响应的协调。一些维护者决策通道是只读的。私人频道是临时的事件室，不是日常开发的场所。有关个人贡献者的事宜可能会保密。

<a id="decision-records" />
## 决策记录

Discord不是记录。针对技术或治理决策的 Discord 讨论必须转移到 GitHub 讨论。每个技术或治理决策，包括 SEP 的核心维护者结果，都写在带有 `notes` 标签的讨论中，或写在 SEP 的拉取请求中。规范更改也记录在[更改日志](/specification/draft/changelog)中，并在这些社区页面中处理更改。

记录列出了做出决定的人、背景、考虑的选项、理由和后续步骤。会议议程和笔记请参见[会议和渠道](/community/working-interest-groups#meetings-and-channels)。
