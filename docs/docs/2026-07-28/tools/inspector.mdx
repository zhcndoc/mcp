[MCP Inspector](https://github.com/modelcontextprotocol/inspector) 是用于测试和调试 [MCP 服务器](/docs/2026-07-28/learn/server-concepts) 的参考开发者工具。它以单个软件包 `@modelcontextprotocol/inspector` 的形式提供，通过一个二进制文件提供**三个客户端**：

| 客户端 | 调用方式                                      | 用途                                                                         |
| ------- | ------------------------------------------- | --------------------------------------------------------------------------------- |
| **Web** | `npx @modelcontextprotocol/inspector`       | 浏览器中的完整图形化检查器。默认选项，也是功能最丰富的界面。  |
| **CLI** | `npx @modelcontextprotocol/inspector --cli` | 可编写脚本、机器可读的客户端，适用于 CI、Shell 管道和编码代理。 |
| **TUI** | `npx @modelcontextprotocol/inspector --tui` | 交互式终端界面，适用于无法使用或不希望使用浏览器的场景。         |

这三者都构建于同一个共享核心之上，因此连接在不同客户端中的行为完全一致：使用相同的传输方式、相同的配置文件、磁盘上相同的 OAuth 状态，以及相同的[协议时代](/docs/2026-07-28/tools/inspector/protocol-eras)协商机制（旧版与现代版 2026-07-28）。

## 快速开始

Inspector 要求使用 **Node 22.19.0 或更高版本**，并可直接通过 `npx` 运行。无需安装：

<Tabs>
  <Tab title="网页">

```bash
# 启动 Web UI 并连接到本地 stdio 服务器
npx @modelcontextprotocol/inspector node path/to/server/index.js

# 或者不指定目标启动，并从 UI 中添加服务器
npx @modelcontextprotocol/inspector
```

该命令会输出一个包含一次性会话令牌的 URL；请在浏览器中打开它。请参阅 [Web 客户端](/docs/2026-07-28/tools/inspector/web)。

  </Tab>
  <Tab title="CLI">

```bash
# 列出服务器的工具并退出
npx @modelcontextprotocol/inspector --cli node path/to/server/index.js --method tools/list

# 调用工具并将结果通过管道传递给 jq
npx @modelcontextprotocol/inspector --cli https://api.example.com/mcp --transport http \
  --method tools/call --tool-name get_weather --tool-arg city=Boston --format json | jq .result
```

请参阅 [CLI 客户端](/docs/2026-07-28/tools/inspector/cli)。

  </Tab>
  <Tab title="TUI">

```bash
npx @modelcontextprotocol/inspector --tui node path/to/server/index.js
```

请参阅 [TUI 客户端](/docs/2026-07-28/tools/inspector/tui)。

  </Tab>
</Tabs>

### 检查已发布的服务器

将用于启动服务器的命令作为 Inspector 的参数传入，或者通过 `--server-url` 指向远程服务器：

<Tabs>
  <Tab title="npm 软件包">

```bash
npx -y @modelcontextprotocol/inspector npx @modelcontextprotocol/server-filesystem ~/Desktop
```

  </Tab>
  <Tab title="PyPI 软件包">

```bash
npx @modelcontextprotocol/inspector uvx mcp-server-git --repository ~/code/mcp/servers.git
```

  </Tab>
  <Tab title="远程 HTTP 服务器">

```bash
npx @modelcontextprotocol/inspector --server-url https://api.example.com/mcp --transport http
```

  </Tab>
</Tabs>

请始终先阅读服务器自己的 README，因为每个服务器所需的命令和参数都不同。

## 启动器标志与客户端标志

`mcp-inspector` 是 `npx @modelcontextprotocol/inspector` 运行的二进制程序，是一个轻量级启动器。它只负责两件事：

1. **模式标志：** `--web`（默认）、`--cli` 或 `--tui`。最多只能指定一个；同时传入两个会报错：`Specify at most one of --web, --cli, or --tui.`
2. **`-h` / `--help`。**

其他所有选项（`--catalog`、`--config`、`--server-url`、`--transport`、`--method` 以及 OAuth 选项）都由_客户端_定义，而不是由启动器定义，并且不同客户端定义的选项集合并不完全相同。[配置与标志](/docs/2026-07-28/tools/inspector/configuration)页面按所属方组织了这些内容。

<Note>
模式标志只会在命令行的开头部分被识别：第一个不是 `--web` / `--cli` / `--tui` 的令牌会结束启动器解析，之后的所有内容都会原样转发给客户端。这使得字面值 `--cli` 可以出现在后面，作为服务器自身的参数：

```bash
mcp-inspector --cli node server.js --cli   # 模式为 CLI；末尾的 --cli 会传递给 server.js
```

</Note>

<Note>
  `--help` 在有无模式标志时的行为不同。不带模式标志的 `mcp-inspector
  --help` 会打印启动器的帮助信息并退出。带有模式标志时，它会被转发，因此 `mcp-inspector --cli --help` 会改为打印 CLI 的完整标志参考。
</Note>
