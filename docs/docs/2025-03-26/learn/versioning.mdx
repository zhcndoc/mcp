模型上下文协议使用基于字符串的版本标识符，遵循
`YYYY-MM-DD` 格式，用于表示最后一次发生向后不兼容更改的日期。

<Info>

只要更新保持向后兼容，协议版本就 _不会_ 随着协议更新而递增。这使得在保持互操作性的同时进行渐进式改进成为可能。

</Info>

## 修订

修订可能会被标记为：

- **草案**：进行中的规范，尚未准备好供使用。
- **当前**：当前的协议版本，已可使用，并且可能继续
  接收向后兼容的更改。
- **最终**：已完成的历史规范，不会再更改。

**当前**协议版本是 [**2025-11-25**](/specification/2025-11-25/)。

## 功能状态

规范的各个独立功能还可以根据
[功能生命周期和弃用策略](/community/feature-lifecycle)标记为
**已弃用**：该功能仍然是规范的一部分，但已计划移除。
已弃用的功能会记录迁移路径（或说明无需迁移），并且在符合该策略的
[加速移除例外](/community/feature-lifecycle#expedited-removal)之前，
至少会保留在规范中十二个月，或者至少九十天，
之后才有资格被移除，随后它们可能会在未来的修订版中被**移除**。

## 协商

版本协商发生在
[初始化](/specification/2025-03-26/basic/lifecycle#initialization)期间。客户端和
服务器**可以**同时支持多个协议版本，但它们**必须**
就会话所使用的单一版本达成一致。

如果版本协商失败，协议提供了适当的错误处理，允许
客户端在找不到与服务器兼容的版本时优雅地终止连接。
