模型上下文协议使用基于字符串的版本标识符，遵循
`YYYY-MM-DD` 格式，用于表示最近一次进行了不向后兼容更改的日期。

<Info>

只要更新后的协议保持向后兼容，协议版本就 _不会_ 递增。这使得在保留互操作性的同时进行渐进式改进成为可能。

</Info>

## 修订

修订可能标记为：

- **草案**：进行中的规范，尚未准备好供使用。
- **当前**：当前协议版本，已准备好使用，并可能继续
  接收向后兼容的更改。
- **最终**：过去的、完整的规范，不会再更改。

**当前**协议版本是 [**2025-11-25**](/specification/2025-11-25/)。

## 特性状态

规范中的各个特性还可以根据
[特性生命周期和弃用政策](/community/feature-lifecycle)
标记为 **已弃用**：
该特性仍然是规范的一部分，但计划被移除。
已弃用的特性会记录迁移路径（或说明不需要迁移），并且在符合该政策的
[加速移除例外](/community/feature-lifecycle#expedited-removal)
之前，会在规范中至少保留十二个月，或至少九十天，
在其具备被移除资格之后，随后它们可能会在未来的修订中被 **移除**。

## 协商

版本协商发生在
[初始化](/specification/2024-11-05/basic/lifecycle#initialization)期间。客户端和
服务器**可以**同时支持多个协议版本，但它们**必须**
就会话中使用的单一版本达成一致。

如果版本协商失败，该协议提供了适当的错误处理，允许
客户端在找不到与服务器兼容的版本时优雅地终止连接。
