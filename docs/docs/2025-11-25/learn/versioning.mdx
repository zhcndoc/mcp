模型上下文协议使用基于字符串的版本标识符，遵循 `YYYY-MM-DD` 格式，用于表示最后一次引入不向后兼容更改的日期。

<Info>

只要协议更新时的变更保持向后兼容，协议版本就 _不会_ 递增。这样可以在保持互操作性的同时进行增量改进。

</Info>

## 修订

修订可能会被标记为：

- **草案**：进行中的规范，尚未准备好供使用。
- **当前**：当前协议版本，已准备好使用，并可能继续
  接收向后兼容的更改。
- **最终**：过去的、完整的规范，不会再更改。

**当前**协议版本是 [**2025-11-25**](/specification/2025-11-25/)。

## 功能状态

规范中的单个功能还可以根据
[功能生命周期和弃用政策](/community/feature-lifecycle)被标记为
**已弃用**：该功能仍然是规范的一部分，但计划将其移除。
已弃用的功能会记录迁移路径（或声明不需要迁移），并且在符合该政策的
[加速移除例外](/community/feature-lifecycle#expedited-removal)之前，
会至少在规范中保留十二个月，或者至少九十天，
之后才有资格被移除，随后它们可能会在未来的修订中被**移除**。

## 协商

版本协商发生在
[初始化](/specification/2025-11-25/basic/lifecycle#initialization)期间。客户端和
服务器**可以**同时支持多个协议版本，但它们**必须**
就会话所使用的单一版本达成一致。

如果版本协商失败，该协议提供了适当的错误处理，允许
客户端在无法找到与服务器兼容的版本时优雅地终止连接。
